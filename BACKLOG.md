  - **NULL-handling contract (load-bearing)** — split guard, NOT a single early-return: each NULL input maps to a *different* semantic, so the function MUST distinguish them rather than collapsing all three to neutral.
    1. **`importance is None`** (genuine missing classification — pre-F25 unit, never classified) → early-return `1.0` (neutral). No signal to drive a boost; default to no-op.
    2. **`last_outcome_at is None`** (unit has never had `record_outcome` called) → early-return `1.0` (neutral). No behavioural signal to anchor decay against; the decay term has no defined start point.
    3. **`stability is None`** (intent_class = permanent — `stability = ∞` by spec) → treat the decay term `exp(-elapsed_days / stability)` as `1.0` (the limit as `stability → ∞`). Do NOT short-circuit to neutral — the formula still evaluates, the importance signal still composes: `boost = 1.0 + decay_alpha × (importance × 1.0 − 0.5)`. A permanent unit with `importance = 1.0` therefore gets a durable importance-based lift (`1.0 + decay_alpha × 0.5 = 1.15` at `decay_alpha = 0.3`) instead of being silently exempted from the composition. This is the deliberate design choice — permanent units are *importance-lifted, not decay-suppressed*.

    Concretely, the function signature and structure are:
    ```python
    def compute_decay_boost(unit, decay_alpha, now: datetime) -> float:
        if unit.importance is None or unit.last_outcome_at is None:
            return 1.0
        if unit.stability is None:
            decay_term = 1.0  # permanent: stability = infinity
        else:
            elapsed_days = (now - unit.last_outcome_at).total_seconds() / STABILITY_SECONDS_PER_DAY
            decay_term = math.exp(-elapsed_days / unit.stability)
        return 1.0 + decay_alpha * (unit.importance * decay_term - 0.5)
    ```

    `now` is an injected parameter (matching F35's `compute_mw_ema_score(success, failure, last_outcome_at, half_life_days, now)` signature pattern), NOT a bare `now()` call inside the function. Callers at the reranker site (`engine.py:1442-1478`) pass through a single `now = datetime.now(timezone.utc)` snapshot per query so all per-unit boosts share a consistent reference time, and unit tests can pin `now` deterministically without monkeypatching.

    Implementations MUST NOT substitute synthetic defaults for `importance` or `last_outcome_at` (e.g., `importance = 0.5`, `last_outcome_at = created_at` at function-call time) — that would silently boost or penalise truly unclassified units. The `stability = None → ∞` mapping is the *only* synthetic value, and it's mathematically equivalent to taking the limit of the closed-form, not a guess. Tests MUST cover all three NULL cases independently: (a) `importance=None` → boost=1.0 (regardless of other fields); (b) `last_outcome_at=None` → boost=1.0; (c) `stability=None, importance=1.0, last_outcome_at=now-30d` → boost ≈ `1.0 + decay_alpha × 0.5` (the importance lift, no decay penalty); (d) all three None → boost=1.0 (the (a)+(b) early-return covers this).

  - **Backfill strategy for existing rows**: the migration inspects the existing `confidence` value and counts incoming `MemoryLink` rows of type `contradicts` / `weakens` (per `packages/core/src/memex_core/memory/contradiction/engine.py:225-227` link convention) to backfill `confidence_evidence_count` non-destructively: for each unit, set `confidence_evidence_count = COUNT(MemoryLink WHERE to_unit_id = unit.id AND link_type IN ('contradicts', 'weakens'))`. **`reinforces` is intentionally excluded** to keep the backfill semantics symmetric with the forward path at `engine.py:211-219`, which only bumps `confidence_evidence_count` on the weaken / contradict steps.   - **Beta prior choice — Beta(1, 1) uniform**: posterior parameters are `alpha = 1 + confidence × confidence_evidence_count` and `beta = 1 + (1 − confidence) × confidence_evidence_count`. ## Cross-cutting requirements

- All MW counters live on **vault-scoped tables** (`UnitEntity`, `MentalModel`, `MemoryUnit`); never on global `Entity` (multi-tenancy invariant)
- All maintenance tasks register under existing `MEMEX_LEADER_LOCK_ID`; no new advisory locks unless F9 (per-entity locks for reconsolidation)
- All new mechanisms emit Prometheus metrics + OpenTelemetry traces (§3.3)
- Hermes plugin (8 Stream-1 tools) updated alongside each MCP-touching feature (§7.5)
- Quality signal is reflection cron + user spot-checks (no formal eval harness — F23 skipped)

## Architectural principles (apply to every feature)

1. **Non-destructive curation by default** — adjust retrieval weights, don't delete
2. **Separate write-time judgment from retrieval-time scoring**
3. **Memory must be observable** (metrics + tracing + diagnostics)
4. **Retrieval-weight composition** — KinthAI principle, MW (F1), FSFM (F11), exploration (F33) all compose at the reranker — same thesis, multiple signals, single composition site (`engine.py:1116`)

See cognitive-memory-research-report.md §3 for full principles.
